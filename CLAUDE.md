# sitebiz — как здесь работают

Бизнес владельца репозитория: находим в 2ГИС компании **без нормального сайта**,
делаем каждой персональный демо-сайт на GitHub Pages, потом обзваниваем владельцев
и продаём то, что уже сделано и открывается по ссылке.

**Цены:** сайт 5 000 ₽ + логотип 3 000 ₽ разово, обслуживание 2 000 ₽/мес.
Правки до публикации бесплатны. В переписке с владельцем цену называем именно так.

Сделано на сегодня: 104 сайта, ниша — автобизнес Новосибирска (`registry.json`).

---

## Железные правила

1. **Ничего не выдумывать.** Каждое утверждение на сайте опирается на карточку 2ГИС,
   отзыв или фотографию. Нельзя писать «работаем 15 лет», «гарантия 2 года»,
   «лучшие цены» — если этого нет в исходных данных. Числа берём из отзывов
   и ссылаемся на них прямо на странице («отзыв в 2ГИС, 11 июня 2026»).
2. **Разработка только в ветке `claude/business-scanner-website-generator-lhf94i`.**
   Пул-реквесты не создаём, пока владелец не попросит явно.
3. **Персональные данные с фотографий убираем до публикации.** Список — ниже.
4. **Каждый сайт визуально не похож на предыдущие.** Одинаковые сайты не продаются:
   владелец сравнивает с сайтом соседа по улице.
5. **Не подключать Google Fonts.** Шрифты лежат локально в `docs/fonts/`
   (17 семейств). Внешний CDN недоступен из песочницы и создаёт трансграничную
   передачу данных, которой в 152-ФЗ лучше избегать.

## Конвейер: от сканирования до готового сайта

### 1. Найти кандидатов

```bash
python3 -m sitebiz scan --city Новосибирск -c "стоматология" -n 300 \
        --min-reviews 20 --min-score 60 -o out/leads.csv
```

Берём тех, у кого **нет сайта** или вместо сайта соцсети/конструктор,
рейтинг от 4.3 и хотя бы несколько десятков отзывов: по отзывам пишется текст,
без них сайт получается пустым.

### 2. Собрать бриф по каждому

```bash
python3 -m sitebiz brief <ЧИСЛОВОЙ_ID> --reviews 30 > out/br/<id>.md
```

**Идентификатор — только ведущая числовая часть.** Из `70000001038911756_abc123`
берём `70000001038911756`, иначе запрос отклоняется:

```bash
echo "$FULL_ID" | cut -d_ -f1
```

Бриф даёт адрес, координаты, режим, телефоны, мессенджеры, список услуг,
30 отзывов с датами и ссылки на реальные фотографии.

### 3. Фотографии

```bash
python3 tools/photos.py fetch out/br/<id>.md docs/<slug>/photo
python3 tools/photos.py sheet docs/<slug>/photo out/sheet.png    # смотрим листом
```

Дальше — **обязательная отбраковка**. Из карточек 2ГИС регулярно приезжает то,
что публиковать нельзя. Реальные находки прошлых партий:

| Что | Почему удаляем |
|---|---|
| Заказ-наряд, квитанция, счёт | ФИО, телефон, VIN, госномер, суммы |
| Скриншот переписки или письма | переписка третьих лиц |
| Приборная панель с горящей ошибкой | это чужое доказательство к жалобе |
| Лица клиентов и сотрудников крупным планом | замазанное лицо выглядит как оперативная съёмка — лучше кадрировать или не брать |
| Каталожное фото на белом фоне, чужой водяной знак | чужая интеллектуальная собственность |
| Фото чужого здания или вывески | нельзя выдавать за своё |

Госномера замазываем **везде**, включая машины на заднем плане:

```bash
python3 tools/photos.py blur docs/<slug>/photo/07.jpg 0.66,0.55,0.80,0.64
python3 tools/photos.py peek docs/<slug>/photo/07.jpg 0.66,0.55,0.80,0.64   # проверить попадание
```

Промахнуться легко — проверяйте `peek` каждый раз. Водяной знак 2ГИС снизу
срезается `python3 tools/photos.py crop`. В конце переименуйте по смыслу
(`rename 19=hero 14=sklad`) — имена читаются в alt-текстах и в истории.

### 4. Написать страницу

Один файл `docs/<slug>/index.html`, всё внутри: стили в `<style>`, скрипты в конце.
Обязательный минимум: `<title>` до 70 знаков, `description` 70–320,
`<meta name="robots" content="noindex,nofollow">` (снимаем только после оплаты),
og-теги, локальные шрифты, JSON-LD, ссылки `tel:`, форма, карта, футер.

Наверху `<style>` — **комментарий на 5–10 строк: почему сайт выглядит именно так.**
Это не украшение: владелец задаёт этот вопрос по телефону, и ответ должен быть
готов. Формулируйте от материала, а не от вкуса («приём взят с их же фотографии
склада: на боковинах маркером написаны размеры»).

### 5. Занести в реестр

```bash
python3 tools/registry_add.py out/new-site.json
```

Скрипт вставляет запись, не переформатируя остальной файл. Статусы:
`новый · позвонил · думает · перезвонить · согласовал · отказ`.
В `message` обязателен плейсхолдер `{URL}`.

### 6. Наложить юридический слой

```bash
python3 tools/build_legal.py
```

Идемпотентно, работает по `registry.json` — **сайт, которого нет в реестре,
скрипт не тронет**. Генерирует `docs/<slug>/privacy/`, вставляет чекбокс согласия,
блокирует кнопку отправки до согласия, добавляет cookie-баннер и заменяет
`<iframe>` карты заглушкой.

Скрипт переписывает дату в 100+ файлах политик. Перед коммитом откатите шум:

```bash
git diff --name-only -- 'docs/*/privacy/index.html' | xargs -r git checkout --
```

### 7. Проверить

```bash
node tools/check/render.js <slug> …     # переполнение, битые фото, ошибки JS, tel:
node tools/check/legal.js               # 152-ФЗ по всем сайтам сразу
node tools/check/shot.js hero <slug>    # посмотреть глазами
node tools/check/shot.js sec <slug> <id-секции>
```

`render.js` разделяет **поломки** (страница сломана у посетителя — чинить сразу)
и **замечания** (длинные `<title>`/`description` — не горит под `noindex`,
но поправить перед публикацией).

### 8. Закрыть партию

```bash
python3 tools/build_catalog.py                 # пересобрать docs/index.html
# добавить новые бизнесы в блок <script id="st"> в docs/obzvon/index.html
node tools/check/legal.js
git diff --name-only -- 'docs/*/privacy/index.html' | xargs -r git checkout --
git add -A && git commit && git push -u origin claude/business-scanner-website-generator-lhf94i
```

Каталог: <https://lttwru.github.io/sitebiz/> · лист обзвона: `/sitebiz/obzvon/`

**Репозиторий публичный.** Владелец знает и согласился, но помните: `registry.json`
и каталог показывают статусы обзвона и заметки по названным компаниям.
Ничего лишнего в комментарии к статусу не пишем.

## Как сайты остаются разными

У каждого сайта свои: **фон, акцентный цвет, пара шрифтов, форма кнопки
и её движение при наведении**. Плюс два обязательных содержательных элемента.

**Структурный приём из собственного материала клиента.** Не украшение, а способ
подачи, вычитанный из его фотографий или отзывов. Примеры из сделанного:
у шиномонтажа размеры написаны маркером на боковинах — все подписи на сайте
набраны моноширинным шрифтом как эти метки; у гаража самообслуживания главный
блок — таблица выбора поста с колонкой «для чего не подходит».

**Честный блок — ответ на реальные минусы из отзывов.** Самый сильный приём
во всей работе. Не «мы лучшие», а «заезд узкий — вот три правила, и вот фото
пикапа, который сюда заехал». Владельцы это ценят, а клиент, который всё равно
прочитает отзывы, получает ответ заранее.

Правила цитирования отзывов:
- 4–5★ цитируем дословно, с именем и датой;
- 1–2★ **не цитируем на сайте** — читаем как список слабых мест и отвечаем текстом;
- не выдёргивать лестное начало из разгромного отзыва;
- явную опечатку в цитате можно молча выправить, но сказать об этом владельцу.

Проверить, не повторяетесь ли со шрифтами:

```bash
cd docs && grep -ho 'fonts/[a-z0-9-]*\.css' */index.html | sort | uniq -c | sort -rn
```

Чего избегать: почти-чёрный фон с одним кислотно-зелёным акцентом, кремовый фон
с терракотой и засечками, фиолетово-синий градиент, эмодзи вместо иконок,
всё по центру. Это выглядит как сайт, сделанный нейросетью, и не продаётся.

## Ниша «медицина»: что здесь строже

В медицинской нише правила жёстче, чем в автосервисах. **Всё ниже нужно
подтвердить у владельца — это не готовая юридическая консультация,
а список того, что нельзя пропустить.**

- **Врачебная тайна (ФЗ-323, ст. 13).** Отзыв, из которого понятен диагноз
  конкретного человека, на сайт не ставим — даже если он опубликован в 2ГИС
  и хвалебный. Цитируем то, что касается сервиса: записали быстро, объяснили
  понятно, не навязали лишнего. Фотографии пациентов, снимки «до и после»,
  рентгены и КТ — только с письменным согласием, которого у нас нет.
- **Реклама медуслуг (ФЗ-38, ст. 24).** Нужно предупреждение о наличии
  противопоказаний и необходимости консультации специалиста. Ставим заметно,
  а не шестым кеглем в подвале.
- **Обязательная информация на сайте медорганизации** (Правила предоставления
  платных медуслуг, ПП РФ № 736 от 11.05.2023): полное наименование, адрес,
  сведения о лицензии — номер, дата, выдавший орган, перечень услуг с ценами,
  сведения о врачах (ФИО, специальность, образование), режим работы, права
  пациента, порядок оказания. **Номер лицензии выдумывать нельзя** — если его
  нет в карточке 2ГИС, оставляем в макете явную заглушку и спрашиваем владельца.
- **152-ФЗ строже.** Сведения о здоровье — специальная категория персональных
  данных. Поэтому форма на сайте: имя, телефон, «перезвоните» — **и никаких
  полей про жалобы, симптомы и диагноз**. Пусть человек расскажет об этом
  по телефону, а не оставляет в форме на GitHub Pages.
- Никаких обещаний результата лечения, гарантий и превосходных степеней
  («лучшая клиника», «100% результат»).
